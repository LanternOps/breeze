# Go 1.27 toolchain bump, then targeted JSON v2 in the agent

This design covers moving Breeze to Go 1.27.4 and then adopting JSON v2 in a few places in the agent.

Status: draft for approval. Date: 2026-11-15.

## 🎯 Intent

Take the free JSON engine speed-up and the safer parsing that Go's JSON v2
offers, without changing what the agent puts on the wire. There is no measured
JSON bottleneck and no target number; this is "don't leave free speed on the
table" plus removing the most fragile hand-rolled JSON in the agent.

JSON v2 cannot be used on the current toolchain. On the pinned Go 1.26.11,
`go list encoding/json/v2` fails with "build constraints exclude all Go files";
it needs `GOEXPERIMENT=jsonv2` there. On Go 1.27 the package builds without a
flag, and plain `encoding/json` is itself backed by the v2 engine (release
notes: unmarshal "significantly faster", marshal "broadly at parity", behaviour
preserved, error text may differ). So the toolchain bump is both the
prerequisite and the largest single gain: it applies to every existing call
site with no code change.

## 🧭 Shape

One tracked feature, two waves.

- **Wave 1:** bump the Go toolchain from 1.26.11 to 1.27.4.
- **Wave 2:** targeted JSON v2 adoption in the agent. Outline only in this
  document; it gets its own design pass when it starts.

Wave 2 is blocked until wave 1 is *done*, and done means: bump merged, a
release cut on 1.27.4, and the fleet promote completed without a rollback.

## 🔎 Upstream context

- No open issue or PR tracks a 1.27 bump.
- Dependabot has proposed the `golang` builder image at 1.27.x four times
  (#9903, #10271, #10914, #11441); each was held at 1.26 because the pin guard
  requires all pins to move together. #11551 (open) proposes 1.27.0.
- The maintainer's position on #10271: a 1.26 to 1.27 change "goes through the
  agent build, so it lands after the v0.125.0 tag as one coordinated change".
  The latest release is v0.129.0. This work is that coordinated change.
- The pin has only ever moved for security fixes (#3523, #8305, #11708).
  Nothing in the repo records a reason to avoid 1.27. Go 1.26 is still
  supported upstream, so there is no deadline.

## 🔧 Wave 1: Go 1.27.4

### 📌 Requirements

- Target is exactly **1.27.4**. It is also the documented **floor**:
  - 1.27.0 and 1.27.1 corrupt the stack on windows/amd64 when
    `runtime.LockOSThread` starts the template thread (golang/go#81731; the
    agent has 29 files using `LockOSThread` and 13 enumerating registry
    subkeys). Backport merged to the release branch on 2026-10-01.
  - 1.27.2 ships a stdlib CVE that Trivy flags (maintainer note on #9903).
  - 1.27.3 lacks the `net/http` security fix that 1.26.11 and 1.27.4 carry.
- If golang/go#82338 (Windows `WriteMsgUDP` reports zero bytes; open, moved to
  the 1.27.5 milestone) proves reachable from the agent, wait for 1.27.5.
  Current evidence says it is not: no non-test code in the agent's Windows
  dependency graph calls `WriteMsgUDP` (pion/transport only declares it on an
  interface and implements it in the virtual test network; `x/net/quic` is not
  compiled in). Stdlib-internal paths to the faulty send routine were not
  traced; the Windows smoke test below covers that gap.

### ⚠️ Behaviour changes in 1.27, checked against the agent

| Change | Finding |
|---|---|
| `compress/flate` output bytes differ (gzip, zip, png too) | Safe. Backup digests are over source bytes (`providers/local.go`), the log shipper and workspace index gzip only for transport, nothing hashes compressed output. Old backups stay readable. |
| `UnixConn` reads return bare `io.EOF` | Safe. The only `net.OpError` check (`recoveryconsole/console.go:815`) tests `Op == "dial"`. |
| TLS `GODEBUG` settings removed | Safe. The agent sets only `x509usefallbackroots`, not on the removed list. |
| `encoding/json` on the v2 engine | Behaviour preserved; error message text may differ. Fix tests that match it. |
| HTTP/1 bodies drain on close; HTTP/2 honours client priority | Low risk; watched through the perf run. |
| macOS 13 minimum | Already the bundle minimum. |
| Closure symbol names simplified | No test inspects symbol names. |

### 🧪 Verified and not verified

Verified on Go 1.27.4 locally: `go build ./...` with cgo off for linux/amd64,
linux/arm64, windows/amd64, darwin/arm64.

Not verified: `go vet` (killed on the dev machine) and the test suite on
1.27.4. The size of the JSON speed-up rests on the release notes and one local
benchmark of a 131 KB report; `perf.yml` settles it.

## 🧩 Wave 2: JSON v2 in the agent (outline)

Agreed:

- Agent only. `scripts/security/yara-pack` is out.
- Targeted conversion, no lint ban on `encoding/json`:
  - `internal/topologycanon/canon.go` `StableJSON`: replace the marshal,
    re-decode, re-encode and U+2028/U+2029 patching with v2 deterministic
    marshalling. The generic-map hop stays: v2 sorts map keys but keeps struct
    field order, so marshalling the struct directly changes digest bytes.
  - the ten production decoders that exist only to set
    `DisallowUnknownFields`.
  - the nil-slice shims such as `collectors/networkcontext/digest.go`.
- Wire bytes stay identical. Any converted site that can emit a nil slice or
  map either sets `FormatNilSliceAsNull` / `FormatNilMapAsNull` or stays on v1.
  Digest parity against `packages/shared` `canonical.ts` is a required test.
- No performance target. Parsers of external tool output (`smartctl`,
  `storcli`, `zfs`, `netsh`, docker labels) stay on v1: v2 makes invalid UTF-8
  fatal and field matching case-sensitive, and both fail silently on fleet data.

Open, for wave 2's own design pass, informed by wave 1's perf numbers:

- whether the work simply waits if 1.27 is refused (recommended: yes, never
  ship `GOEXPERIMENT=jsonv2`)
- whether the ten strict decoders may also reject duplicate keys and invalid
  UTF-8 in commands from the API
- benchmark evidence in the PR versus a CI performance gate
- whether `jsontext` streaming is worth it for the `json.RawMessage` sites

## ⚖️ Approaches considered

1. **Pins-only bump PR, then JSON as a second wave (chosen).** A toolchain
   regression is attributable and reverts in one commit; wave 2 starts from
   measured numbers.
2. **`GOEXPERIMENT=jsonv2` on 1.26.11.** No bump needed, but ships a code path
   the Go team does not support on that branch into binaries on customer
   machines. Rejected.
3. **Bump and JSON conversion in one PR.** Fewer releases, but a regression
   cannot be separated into toolchain versus JSON semantics. Rejected.
4. **Repo-wide v1 ban with a lint rule.** After the bump v1 already runs on
   the v2 engine; converting 776 files buys little and imports case-sensitive
   matching and fatal invalid UTF-8 everywhere. Rejected.
