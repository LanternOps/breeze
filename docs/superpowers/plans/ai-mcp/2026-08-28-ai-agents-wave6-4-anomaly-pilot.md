# Wave 6 PR 4 — Metric-Anomaly Pilot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Metric anomalies become a **first-class `anomaly` trigger kind** for AI agents (never disguised as an alert), fed by a **canonical incident row per device/type/window** that collapses sibling detector rows and carries a **transactional dispatch marker** so bulk detector re-upserts can never re-publish. Anomaly-triggered runs are **shadow-forced** (pilot: an unproven detector must never drive act mode), **cross-deduped** against the alert path via the existing `metric_anomalies.linked_alert_id` linkage, and gated by real trigger filters — including the long-deferred **`deviceGroupIds`** filter, implemented FIRST because every device-bound trigger (alert AND anomaly) needs it.

**Architecture (grounded in the dossier, 2026-08-28):** The detector job (`services/metricAnomalies.ts`, three `INSERT … ON CONFLICT DO UPDATE` statements per `detect-org-range`, 10-min schedule over a 30-min lookback → each row revisited ~3×) gains a fourth statement that upserts **`metric_anomaly_incidents`** keyed exactly on the promotion path's collapsing key `(org_id, device_id, anomaly_type, bucket_seconds, window_start)` — `metric_name` deliberately excluded, mirroring `metricAnomalyPromotion.ts:107` `findDedupeSiblings`. The incident row IS the outbox: `dispatched_at`/`dispatch_attempts`/`agent_run_id` columns; the upsert's `DO UPDATE` only refreshes `last_seen_at`/`peak_score`/`row_count` and **never touches `dispatched_at`**, which is what makes re-upserts publish-inert by construction. A publisher worker (`metricAnomalyIncidentPublisher`, clone of `ticketOutboxPublisher`'s claim loop: `UPDATE … WHERE dispatched_at IS NULL … FOR UPDATE SKIP LOCKED RETURNING`, publish OUTSIDE db context, mark dispatched, alarm stuck rows) publishes `anomaly.incident_opened` onto the generic event bus with an **id-only payload** `{ incidentId, deviceId }`. A durable subscriber `ai-agent-anomaly` admits `createAndEnqueueAgentRun({ triggerKind: 'anomaly', anomalyIncidentId, deviceId, dedupeKey })` for enabled agents whose trigger filters match. **Cross-dedupe:** if any sibling `metric_anomalies` row of the incident has `linked_alert_id` set, the dedupe key is `alert:<linkedAlertId>` (colliding on the same `(org_id, dedupe_key)` unique index the alert-triage path uses), else `anomaly:<incidentId>`. Reverse direction (human promotes AFTER an anomaly run exists) is a documented v1 deferral — promotion is manual and rare.

**Design authority — LOCKED (wave-6 quorum 2026-08-28) + dossier corrections:** `anomaly` is its own trigger kind (its own run column `ai_agent_runs.anomaly_incident_id`, its own context assembler, its own filters — never an `alerts` row in disguise); canonical incident collapses siblings; dispatch is transactional (marker on the canonical row) so bulk upserts are inert; cross-dedupe vs the alert path; **`deviceGroupIds` trigger filter ships FIRST** (Task 1) and applies to BOTH the alert path (`evaluateAgentTriggerFilters` — docstring at `runService.ts:167` says "deliberately NOT evaluated") and the anomaly path, via an org-pinned `device_group_memberships` lookup (pattern: `alertService.ts:444`). Forced shadow for anomaly runs (mirror PR 3's `ticketId` conditional at `runService.ts:483` AND the caller-guard that rejects `anomalyIncidentId` with a non-`anomaly` triggerKind). Anomaly runs are device-bound (unlike ticket runs) — shadow means tools propose, never execute; the run still passes device pinning/site checks. Dossier corrections: no automatic anomaly→alert promotion exists (promotion is a manual `PATCH /devices/:id/anomalies/:anomalyId/status`), so the "re-publish on bulk upsert" hazard is latent until THIS PR adds the hook — the marker design is what keeps it latent; the alert↔anomaly linkage already exists (`linked_alert_id` + `alerts.context.anomalyId`) — reuse, don't rebuild.
