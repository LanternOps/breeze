# Tool Catalog — Wave 5: Webhook Trigger, Flows as Tools, Concurrency, AI/HTTP Steps, Budgets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An external system fires a signed webhook that starts a flow in the right org; a flow calls an outside HTTP API, sends a notice to a channel and asks the AI one bounded question; an enabled manual flow is a tool that chat, Breeze's MCP server and an AI agent can call at that flow's own tier; for-each items run in parallel; and every run is counted against monthly caps that refuse visibly instead of failing silently.

**Architecture:** Every new run path ends in W04's `createFlowRun`, so dedupe, the active cap and the admission seam apply unchanged; W05 widens `assertFlowRunAdmission` with exact monthly counters charged inside the same system transaction as the run insert. The webhook is a public router (`/api/v1/webhooks/flows/:flowId`) that verifies the Breeze HMAC scheme already used by automations and outbound webhooks against a per-flow encrypted secret, dedupes durably in a `flow_webhook_deliveries` log, resolves a partner-wide flow's org through `organization_external_links`, and creates a `webhook` run that never honours pre-approvals. Flows-as-tools are descriptors built per caller from enabled manual publications; their tier is resolved live at call time (`max(recorded, recomputed)`) in chat, MCP and the agent path; a Tier-3 call in chat becomes an action intent carrying an immutable `invoked_flow_id` binding that the existing release worker turns into a `tool` run, MCP refuses Tier 3, and agents may start only Tier-1 flows from runs without a device/site ceiling. Built-ins stop bypassing authorization: they join rule 7, run-time revalidation and Tier-3 parking (an approved built-in executes through the release worker). The three new built-ins run in-process from `services/flows/builtins/`: `http_request` anonymously through `urlSafety.safeFetch` with a literal origin and an absolute deadline, `notify` through a new generic channel-message sender, and `ai` as a bounded Messages-API tool loop over Tier-1 tools that charges the run org's existing AI budget.

**Tech Stack:** TypeScript, Zod 4, Hono, Drizzle (queries only), hand-written SQL migration, Postgres forced RLS, BullMQ, Redis rate limiter, Anthropic Messages API via `aiModels/connectionFactory.ts`, Vitest, React + Astro + react-i18next (8 locales).

**Spec:** `docs/superpowers/specs/ai-mcp/2026-09-07-tool-catalog-and-flows-design.md` — §6.1 (webhook trigger, built-ins), §6.2 (templating), §6.3 rules 1/6/7, §6.5 (execution org for webhooks, limits), §6.6 (flows as tools), §6.7 (budgets), §6.8 (webhook panel), §8 (webhooks in, egress, secrets), §9; the W4 amendments (§6.3 Decisions 3/4/13, §6.4, §6.5, §6.6 Decision 11, §6.8, §8, §11 "Deferred to W05").
