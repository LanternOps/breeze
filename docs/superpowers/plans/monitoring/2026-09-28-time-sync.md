## Review focus (spec-implied inputs no single task's tests would otherwise exercise)

1. **A failure event followed by a success, then the same failure again** (DNS flaps) — event 134 at
   10:00, event 37 at 10:05, event 134 at 10:40: the finding must be active at 10:40 and not at
   10:10. Pinned in W01a `findings.test.ts` (§C.4 rule) with exact timestamps.
2. **A non-English Windows** (German display language) — the snapshot must equal the English one
   field-for-field except `events[].message`. W01b lab L9 plus a unit test that feeds the status
   parser German `w32tm` text and asserts only locale-independent fields are extracted.
3. **An `NtpServer` value an admin typed by hand with odd spacing and flags**
   (`"  time.a.com,0x9   time.b.com,0x8  "`, `"time.a.com,0x1,0x8"`, empty string) — the resolver's
   host parsing must yield `["time.a.com","time.b.com"]` / `["time.a.com"]` / `[]` and never raise
   `ntp_server_unresolvable` for a well-formed host with flags. W01a `ntpServerHosts.test.ts`.
4. **A site whose timezone is `UTC` and a device on `Pacific Standard Time`** — no
   `timezone_mismatch`; the view shows "No expected timezone (site uses the UTC default)". W01a
   `expectedTimezone.test.ts` + view test.
5. **An agent restart that resets `sequence` to a lower number** — ingest must accept the first
   snapshot whose `collectedAt` is more than 1 h newer than the stored `collected_at` even when
   `sequence` went backwards (reset rule), and reject true duplicates. W01a ingest test.

**C.3 Findings** — `findings.ts`, pure:

```ts

`findings` are ordered by `TIME_SYNC_FINDING_CODES` order, each code at most once. `health` = worst
of `critical`/`warning` present; else `unknown` when `snapshot.status.method === 'unavailable'` and
no finding at all; else `healthy` (`info` findings never lower health). Raise rules are spec §5.2
verbatim; `detail` keys per code:

| code | detail |
|---|---|
| `pdc_no_external_source` | `{ domainDns }` |
| `source_local_clock` | `{ source, sourceKind }` |
| `dc_vm_host_sync` | `{ role }` |
| `ntp_server_unresolvable` | `{ host }` (first bad host, or the event 134 `properties[0]`) |
| `ntp_peer_unreachable` | `{ source }` (event `properties[0]` or `status.source`) |
| `domain_source_unavailable` | `{ domainDns }` |
| `member_not_on_hierarchy` | `{ type }` |
| `sync_disabled` | `{ reason: 'no_sync' \| 'service_disabled' }` |
| `sync_stale` | `{ lastSuccessfulSyncAt, thresholdHours }` |
| `correction_refused` | `{ occurredAt }` |
| `timezone_mismatch` | `{ actual, expected, expectedIana, expectedSource, expectedSourceName }` |
| `policy_not_applied` | `{ kind, reason, error }` (W03a) |
| `policy_conflict_gpo` | `{ values }` (W03a, comma-joined `policyManagedValues`) |

**C.4 Event activity rule (spec §5.3, exact).** New `eventMarks` = `previousEventMarks` merged with
this snapshot's events (per id keep the max `occurredAt`), then drop entries older than 7 days. For a
failure id `E` with mark `m`: active ⇔ `now − m ≤ TIME_SYNC_EVENT_ACTIVE_WINDOW_MS` **and**
`m > max(mark[35], mark[37], status.lastSuccessfulSyncAt)` (missing values = −∞).

              expected: ExpectedTimezone | null; expectedUnsetReason: 'site_utc_default' | 'no_site' | 'unmapped' | null } | null;
  recentEvents: Array<{ recordId: number; eventId: number; level: number; occurredAt: string; message: string }>;
  enforcement: TimeSyncEnforcementState | null; // W03a (§F.3); W01a returns null
}
export async function getDeviceTimeStatusView(deviceId: string): Promise<DeviceTimeStatusView | null>; // null = device not visible
```

`state = 'unsupported_os'` when `devices.os_type !== 'windows'` and no row; `'not_reported'` when
Windows and no row. `stale` = `now − received_at > TIME_SYNC_STALE_AFTER_MS`. The expected timezone
is **re-resolved at read time** (site may have changed since ingest) and `timezone_mismatch` in
`findings` is recomputed from it, so the view never shows a stale mismatch.

## Contract resolutions (2026-09-29, after the five plan drafts)

Binding; they override anything above or in the spec that conflicts. Each plan's `## Contract
issues` section was triaged into these.

- **R1 Locales — translate, never copy English.** `apps/web/src/lib/i18n/translationCoverage.test.ts`
  (~1092–1140) caps exact-English duplicates per locale and namespace, and several locales are already
  at their `devices` cap. Every new key gets a real translation in all seven non-English catalogs
  (de-DE, es-419, fr-CA, fr-FR, it-IT, pt-BR, tr-TR). Where a value is legitimately identical in a
  locale (protocol or product tokens such as `NTP`, `W32Time`, `NT5DS`, `Stratum`), raise that
  namespace's baseline by exactly that count with a `// +N: <key> — <reason>` comment, as the existing
  `+1` entries do. Never raise a baseline for prose.
- **R2 Windows zones.** CLDR has no Windows zone for a few IANA ids the picker offers (e.g.
  `Antarctica/Troll`). The coverage test asserts "every picker zone maps, except an explicit, named
  allowlist of CLDR-unrepresentable zones"; those resolve to `null` with `expectedUnsetReason:
  'unmapped'`.
- **R3 Fix hints.** Hint placeholders not present in `detail` (`{device}`, `{site or policy}`) are
  filled by the web presentation layer from the parent view (device display name,
  `expected.sourceName`/`expected.source`). `detail` shapes stay as §C.3.
- **R4 Collector freshness (replaces any pending/acknowledge design).** `Collect(ctx)` performs fresh
  reads on every call and returns a new snapshot with `sequence = last + 1`. Only two things persist in
  `timesync-state.json`: `sequence` and the event cursor `eventsSince`. `(*Collector).Commit(snapshot
  *Snapshot) error` advances `eventsSince` to `snapshot.CollectedAt` and is called by the sender only
  after the API answers 2xx (`accepted: true` **or** `accepted: false, reason: 'stale_sequence'`). A
  failed send changes nothing, so the next run re-reads the same events with a new sequence. W03b's
  pre-write guards read through `System` directly, never through a cached snapshot.
- **R5 Events.** The snapshot's `events` = (Time-Service events since `eventsSince`, all levels) ∪
  (the newest 20 Time-Service events of any age), de-duplicated by `recordId`, newest first, capped at
  100 with the display tail reserved, and trimmed to fit a 256 KiB serialized budget.
- **R6 Policy management fails closed.** Any error reading the `Policies\Microsoft\W32Time` keys other
  than "key not found" sets `policyManaged = true` (and `policyManagedValues` to what was readable).
- **R7 Status source.** Method 1 (`W32TimeQueryNTPProviderStatus`) ships only if the W01b spike cites
  its prototype and buffer-ownership rules from the installed Windows SDK `w32time.h` on the lab VM
  and it passes the L1/L3/L5/L9 comparison. Otherwise W01b ships the fallback ladder (tokens, then
  events 35/37) — approved in advance. `sourceKind` reports only kinds the chosen method proves; the
  rest are `unknown`. If lab evidence disproves an event-ID meaning in §A, fix it in a small API PR
  before the W01b agent release.
- **R8 Service state.** `svcquery.GetStatus` is kept for other callers; the time collector adds its own
  raw SCM read so `paused`, `*_pending`, `delayed_auto` and `trigger_manual` survive.
- **R9 Exec helper.** Add exported `collectors.RunCollectorOutput(ctx, timeout, name, args...)` as a
  thin wrapper over the existing unexported bounded runner in
  `agent/internal/collectors/command_limits.go`; `timesync` uses it.
- **R10 L9 equality.** Unit level: a fixed-input replay must be field-for-field equal except
  `events[].message`. Lab level: compare stable fields; `sequence`, `collectedAt` and new events may
  legitimately differ.
- **R11 Alert handler.** Missing or stale row → every selected code gets `unknown` evidence,
  `dataAvailable: false`. Alert context: `{ source: 'time_sync', findingCode, findingLabel,
  findingDetail, domainRole, timeSource, lastSuccessfulSyncAt }`. W02 makes two narrow, tested fixes to
  the subject pipeline: `services/alertSubjects.ts` must not stamp every subject source as
  `hardware_health`, and the maintenance-suppression recovery path in `services/alertService.ts` must
  accept `time_sync` subjects as well as hardware ones.
- **R12 Daily rollup.** "Latest" means latest accepted snapshot in ingest (serialized) order.
  `worst_health` order for the daily row: `critical > warning > unknown > healthy`.
- **R13 Navigation.** The fleet page entry sits next to Fleet Posture under Reporting
  (`apps/web/src/components/layout/Sidebar.tsx` ~357); the URL stays `/devices/time`.
- **R14 Reconcile compare.** Domain-hierarchy roles compare only `Type` (`NT5DS`/`AllSync`) and the
  W32Time start type/state; host list and `SpecialPollInterval` are compared only for manual-peer roles.
  `/reliable:yes` is sent on every forest-root PDC apply and verified in lab L7 (no wire field).
- **R15 Timezone validation on the agent.** Before `tzutil /s`, the agent checks that
  `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Time Zones\<id>` exists (plus a syntax check),
  instead of an embedded list. The server still validates with `isKnownWindowsZone`.
- **R16 Branch names** follow CLAUDE.md's feature-lifecycle rule (`feature/<parent#>-<slug>/wave-<sub#>`),
  which overrides the generic `feat/<issue>-<slug>` convention for tracked waves.
- **R17 Code style in plans.** Go blocks must be `gofmt`-formatted; TS blocks follow the repo's
  prettier style. Executors run `gofmt -l` / the linters before committing.
