## What the vertical test proves (real routes, real adapters, real Postgres)

Fixture: `apps/api/src/__tests__/helpers/topologyPhysical.ts`, re-exported from
the M1 seed (`helpers/topologyM1.ts`). SNMP adjacency is posted through
`POST /agents/:id/topology/adjacency` under a persisted D7 dispatch snapshot;
UniFi through `POST /agents/:id/unifi-telemetry` with the `topologyV1`
companion; publication through `reconcileTopologySite`. Inspection goes only
through the authenticated graph, detail, evidence, exclusions and nodes routes.

1. **Enrichment over the no-management baseline:** the agent's default route and
   subnet membership keep their ids and stay active; reciprocal LLDP combines to
   one link per cable (support 2); two parallel cables stay two links on distinct
   ports; the FDB-only attachment is `attachment`/`unknown` directness/`selected`;
   the desk NIC learned on two access ports is two `competing` candidates with
   each other as alternatives (ambiguity visible); a Q-BRIDGE port with 20 MACs
   persists as one `shared_port` row and mints no per-MAC endpoint; UniFi VPN is
   an `attachment` with `unknown` directness and `vpn` association (never a cable,
   never radio); the legacy agent's port-less adjacency stays its own relationship;
   the imported legacy pin and saved v2 pins are unchanged; reads write and
   dispatch nothing.
2. **Timeouts and withdrawal:** a partial LLDP walk and a partial controller
   client page keep all existing support; complete-empty from one switch, then
   the same body confirmed 6 minutes later on the fixture clock (report
   `capturedAt`, no sleeps), withdraws only that switch's support — links stay
   active on the peer's support and every other relationship keeps its lifecycle;
   a reconcile worker that dies before COMMIT leaves support and graph revision
   untouched, and the retry applies the transitions.
3. **Source remap:** remapping the controller site away withdraws only UniFi
   attachments; remapping back re-baselines under one fresh epoch and the same
   relationship ids return to active.
4. **Rollback and parity:** physical off hides collected physical evidence
   (manual and legacy rows are never gated) while collection and capture continue;
   a legacy rename, pin move and manual-edge deletion plus a v2 layout edit made
   while off all land; after re-enable the same link ids and the v2-only manual
   assertion are visible without reprojection; the six-field report above.
5. **Bounded projection at G10K scale** (10,000 nodes / 20,000 relationships,
   4,000 physical): the physical view returns exactly 1,000 nodes and at most
   2,000 edges with `counts` equal to the fixture's own physical sub-graph
   (exact omitted counts) and a frontier; overview reports 10,000 / 20,000 totals.

## Findings from running the gates

- **Fixed (`dd96a7908`):** the M1 topology browser gate (`topology-browser-gate`,
  a `ci-success` dependency) failed 2/14 on this branch with
  `script-src: eval …/schemas.*.js`. Cause: `PhysicalCoveragePanel` imported a
  constant from the `@breeze/shared` barrel, which constructs zod object schemas
  before `validators/topologyZod` sets `jitless`. A control rebuild with the
  Step 0 web/shared edits reverted failed identically, so it predates Task 10.
  A source-scan unit test now forbids runtime barrel imports in the topology UI.
- **Open, not fixed:** `topology_relationships` has no index on
  `source_node_id` / `target_node_id`. At G10K scale, straight after a bulk load
  (no planner statistics), the physical-view node count did not finish within
  120 s; after `ANALYZE` the same read completes in seconds. The test analyzes
  after its bulk load (a real site is auto-analyzed as it grows). An
  uncorrelated-subquery rewrite of the membership predicate was measured
  (~3× faster test time) but not kept, since it was not required to pass the
  gate. A fast-growing site before autovacuum's first analyze could hit the
  slow plan; follow-up recommended.
- **UX paper cuts (not fixed):** the relationship inspector heading shows the raw
  kind (`physical_link`); `/discovery?orgId=` does not switch the org store (the
  spec selects the org through the persisted store instead).
- **Stack traps met:** the worktree needed a root `.env` with a non-overlapping
  `BREEZE_DOCKER_SUBNET`/`BREEZE_CADDY_IP` and `BREEZE_WORKSPACE_ENABLED=false`
  (no pgvector); `wt-stack up` failed twice on the api healthcheck during a slow
  first boot, so the descriptor was written by hand once all services were
  healthy. The stack was torn down (`pnpm wt-stack down`) after the runs.
