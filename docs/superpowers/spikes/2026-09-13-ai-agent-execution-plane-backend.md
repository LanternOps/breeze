# Spike — Execution-plane backend for AI agent workspaces (rent vs build)

**Date:** 2026-09-13 (desk research; all vendor facts fetched from official docs this day)
**Status:** 🟢 **QUORUM REACHED (Fable + Codex gpt-6-astra xhigh, 2026-09-13): rent-first on Vercel for a bounded v1, with the corrections in §H — awaiting Todd's decision**
**Gates:** the forthcoming spec `docs/superpowers/specs/ai-mcp/2026-09-XX-ai-agent-execution-plane-design.md` (sub-project 1 of 3: sandboxed workspace). Amends `2026-08-22-ai-agents-program-and-wave1-design.md` §2 ("never per-run containers").

Labels: **V** = verified against a fetched official URL on 2026-09-13; **U** = unverified (secondary source, inference, or absent from docs). Full per-pass findings live in the session transcript; this doc keeps only what decides the question.

## Question

Breeze AI agents (chat, autonomous runs, AI Operator) can act on a fleet safely but cannot *work*: no filesystem, no code execution, every byte through model context, one device per run. Decisions already taken in brainstorming:

- keep our loop (Claude Agent SDK + our MCP tools + tiers + kill switch) in the API/worker;
- per-run **ephemeral compute**; run-scoped read/write artifact area; read-only mounts of org data; no writable filesystem that persists across runs;
- sandbox is **network-isolated** except a brokered, read-only *fetch artifact* capability; every fleet action still goes through the loop's tier-gated tools;
- **hosted only** (this is the paid channel).

Which backend hosts the sandbox? Five hard requirements: **(1) egress** deny-all with a one-host allowlist enforced outside the guest; **(2) residency** EU-for-EU, US-for-US, guaranteed; **(3) metering** per-run CPU/memory/duration via API; **(4) control plane** callable from plain Node over REST/SDK, no vendor edge runtime; **(5) secrets** injected per run, never in the image.

## Answer in one paragraph

Rent first, build second, same interface either way. **Vercel Sandbox** is the only vendor that meets all five requirements as documented (Firecracker microVM, `deny-all` egress including DNS with a single-host allowlist, five selectable EU regions, per-sandbox CPU-ms and duration via SDK, plain access-token REST, proxy-side credential brokering, GA 2026-01-30). **Modal** and **E2B** are close seconds, each missing one requirement. **Cloudflare** now has GA containers with egress allowlists and EU jurisdiction but requires a Worker + Durable Object as control plane. On **DigitalOcean** nothing is callable today except droplets: the self-host shape is a per-region warm pool of droplets running **gVisor (systrap)** containers, one per run, with **Cloud Firewall** deny-all outbound and a per-run unix-socket broker — strong, cheap, and the same runtime DO uses for App Platform, but it makes us own a sandbox security boundary. Firecracker/Kata/microsandbox are off the table on droplets: nested KVM is exposed but DO calls it unsupported and live migration kills nested VMs. DO's own "Managed Sandboxes" (E2B-compatible, Firecracker) was announced GA in a May 2026 blog post but has no docs page, API, pricing, or region list; watch it. Because Vercel, E2B, and DO's future product all expose an **E2B-shaped API** (create / exec / write / read / destroy / usage), designing our backend interface to that shape gives us portability to the self-host pool and to DO's product for free.

## C. Self-host shape on droplets (if/when we build)

One **gVisor (runsc, systrap)** container per run on a sandbox-only worker droplet per region. All enforcement points are host-side:

- **Launch:** `--runtime=runsc --network none --read-only --tmpfs /tmp --memory 1g --memory-swap 1g --cpus 1 --pids-limit 256 --cap-drop ALL --security-opt no-new-privileges --init`, image pinned by digest, runsc overlay upper layer capped in memory **V** (Docker + gVisor docs).
- **Egress:** `--network none` gives the container no interface at all (a host netns decision the guest cannot undo) **V**; the one path out is a **per-run unix socket** bind-mounted from the host and served by our broker (the Anthropic `sandbox-runtime` and Docker Sandboxes pattern) **V**. The socket path identifies the run without any token in the guest. **Unverified:** gVisor gates host UDS behind a `--host-uds` flag — confirm before relying on it **U**; fallback is a dedicated bridge with `iptables -I DOCKER-USER ... ! -d <broker> -j DROP` **V**. Docker 29's experimental nftables backend has no DOCKER-USER chain — pin the backend **V**. Cloud Firewall deny-all outbound on the droplet is the second, provider-enforced fence **V**.
- **Secrets:** none in env, image, or volumes; the broker holds credentials and injects them upstream **V** (Docker Sandboxes model). Never mount the Docker socket **V**.
- **Metering:** after `wait?condition=not-running` and before `rm`, read cgroup v2 `cpu.stat usage_usec`, `memory.peak`, `memory.events oom_kill`, `pids.peak`; `docker inspect` for wall time **V**. Sentry threads live in the run's cgroup, so gVisor overhead is billed to the run — document it **V**. Don't use `--rm` (destroys the evidence) **V**.
- **Teardown:** deadline timer → `docker kill` → collect → `docker rm -v` → wipe `/srv/runs/<id>`; reaper cron for orphans **U (ops pattern)**.
- **Cost:** ≈ 1 run per vCPU minus ~15–20 % overhead; a 1 vCPU/2 GB droplet at $0.018/h vs ≈ $0.17/h per run at Vercel → 5–10× cheaper at steady volume **V prices / U overhead**.

**Risks:** single software boundary (gVisor is a user-space kernel, not a VM) — mitigate with sandbox-only droplets holding no tenant data at rest, rebuilt on schedule **V/U**; file I/O is gVisor's most-impacted workload **V**; io_uring off, some native wheels may fail **V**; no escalation path to microVMs on DO — bare metal or another provider if a hardware boundary ever becomes mandatory **V**.

## D. Open-source patterns to borrow (and regrets to avoid)

Borrow:
1. **No netns + host broker on a bind-mounted unix socket** — `anthropics/sandbox-runtime` **V**. Adopt its proxy/allowlist design as our broker and inner fence (TS, Apache-2.0, beta); it is process-level, so not the outer boundary.
2. **Controller dials *in* to an in-sandbox daemon** (fs/process/PTY/watch API), boot-time token via metadata, internal routes unreachable — E2B `envd` **V**. Avoids OpenHands' recurring `host.docker.internal` failures **V titles**.
3. **Late-bound warm pool**: box boots before the run exists, dispatcher posts `{run_id}` in — kubernetes-sigs/agent-sandbox × Managed Agents **V**.
4. **Credentials outside the boundary, injected by the proxy** — Docker Sandboxes **V**.
5. **Persisted-output handle**: tool results over a cap go to the artifact store and return `{handle, bytes, head, tail}`, materialisable inside the sandbox via `fetch_artifact(handle)` — Claude Code's `tool-results/` mechanism **V**, corrected by its own bug history (below).
6. **Per-run secret distinct from the environment key; SIGTERM ≥ 30 s for final upload** — Managed Agents self-hosted **V**.
7. **Hard budget enforced between model requests with a `budget_reached` stop reason** — Managed Agents sessions **V**. Ours already exists for tokens; extend the same gate to compute.

Avoid:
- **Truncation without a handle → retry loops.** Codex: 256 lines / 10 KiB head+tail; one session grew from ~21 k to ~194 k input tokens over 51 calls (#40897) **V**. OpenHands drops the middle of >30 KB outputs; offloading proposal closed "not planned" (#12353) **V**.
- **Persisting rendered output.** Claude Code re-persisted line-numbered output four levels deep (#31686), broke JSON tool responses (#17944), and duplicated 5 MB into the transcript so resume hung (#23948) **V**. Persist raw bytes; keep the transcript to the handle; let tools opt out.
- **Metadata endpoint ambiguity.** E2B's `denyOut` did not block MMDS (#3625) **V**. Hard-deny metadata, link-local, loopback and private ranges regardless of policy, as sandbox-runtime and Sprites do **V**.
- **"Self-hostable" with a vendor control plane.** E2B Embed is "single-machine evaluation packages rather than deployment patterns" and ships an unauthenticated orchestrator gRPC port; prod = Kubernetes or GCP/AWS Terraform **V**. Daytona's public repo is frozen; BYOC keeps the control plane hosted **V**.

## E. What Breeze already has that this reuses

- **`services/llm/llmEgressProxy.ts`** (BYO-LLM wave 2): CONNECT-only proxy, single-use bearer per grant, CONNECT target must equal the granted host, DNS resolved and the *IP* dialled, blocked attempts audited to `llm_egress_events` — the exact enforcement shape for the broker. Needs: grants keyed to a run, more than one destination, and a plain-HTTP decision.
- **`org_documents`** (service-deliverables spec §4.4, designed, unbuilt): `s3|db` blob store with tenant-keyed erasure — the natural artifact area.
- **AI Operator completion spec §6–7 + P3-0 baseline contracts §1**: checkpoints, lease fencing, waits, reconciliation, 72 h task budgets, and the typed `admit/dispatch/observe/verify/cancelIfSupported/reconcileUnknown` adapter — the checkpoint/resume interface for long work is already written.
- **Agent builder tool catalog** (`agentToolCatalog.ts`): where a sandbox capability is exposed — not a second picker.
- **Tier/intents layer**: unchanged; the sandbox mints no intents and executes no fleet action.

## F. Recommendation

1. **Interface first, E2B-shaped.** `SandboxBackend { create(spec) → handle; exec(handle, cmd, {env, timeout, stream}); writeFile / readFile / listFiles; usage(handle) → {cpuMs, peakMemBytes, wallMs}; destroy(handle) }`, plus a `Broker` that mints a per-run capability and serves `fetch_artifact` only. Vercel, E2B, DO's announced product and our own pool all fit this shape.
2. **v1 backend: rent — Vercel Sandbox.** Meets all five requirements today, GA, microVM boundary, per-run metering straight from the SDK into credits, EU regions by parameter. At 1 vCPU a 10-minute run costs ≈ 3 ¢ at full CPU, inside the existing 50 ¢ per-run budget. We do not take on a sandbox security boundary before the workload proves demand. Keep Modal as the fallback if per-sandbox metering ships there or wall-clock attribution is acceptable.
3. **v2 backend: build — gVisor pool on DO droplets** (§C), triggered by volume economics (≈5–10× cheaper) or a vendor risk (SNI fronting, residency wording, pricing). Same interface, no loop or tool changes.
4. **Watch DO Managed Sandboxes.** E2B-compatible + Firecracker + our provider; if it ships publicly with region pinning and egress policy it may pre-empt v2.
5. **Broker and artifacts:** extend `llmEgressProxy` to run-keyed multi-host grants; build `org_documents`; persisted-output handles with raw bytes and head+tail previews; hard-deny metadata/private ranges regardless of policy.
6. **Amend wave1 §2 by name** in the spec: "never per-run containers / the SDK child is the isolation unit" is reversed for the workspace lane, with this document as the reasoning. The SDK child remains the isolation unit for the *loop*; the sandbox is the isolation unit for *model-written code*.

**Subprocessor note (V):** Vercel Sandbox's region table labels every region with an AWS region name (`fra1 = eu-central-1`) but no fetched page states "runs on AWS"; E2B's host cloud is unstated; Modal names no provider. Choosing AgentCore directly removes one layer from the chain if Vercel is indeed on AWS.

**Hostname allowlists (G):** no hyperscaler enforces a *hostname* allowlist natively; all give IP-based security-group/firewall control, so a public broker hostname needs NAT or a proxy in front. AgentCore's SANDBOX mode plus IAM-scoped S3 sidesteps this entirely: no network, files exchanged through a bucket prefix the session's execution role can reach.

**Ops burden for a 1–2 person team with no hyperscaler footprint (G):** AWS = organization + IAM roles (execution role trusting `bedrock-agentcore.amazonaws.com`, API role for our Node backend), S3 buckets per region, CloudWatch vended-log delivery for metering, cost tags, quotas; VPC mode adds per-region VPCs, SGs, NAT or PrivateLink. Azure = lightest setup, least control. GCP = project, service accounts, Artifact Registry, per-region VPC sized for concurrent tasks.

**Effect on §F.2:** two v1 candidates now, not one.
- **Vercel Sandbox** — simplest: hostname allowlist, no cloud account, per-sandbox metrics in the SDK. Weaker on residency evidence (DPA, London not EU) and metering fidelity (CPU after stop, allocated not peak).
- **AWS AgentCore Code Interpreter** — stronger on residency (seven EU regions, AWS DPA/compliance maturity), metering (1-s per-session usage logs), and isolation (SANDBOX mode = zero network, S3 as the only path), GA on a hyperscaler. Costs an AWS footprint and IAM/S3/CloudWatch plumbing, and lacks a per-session secret parameter and (as far as docs show) custom images.
The private adapter (§H.5) is identical for both. Pick after Todd's Vercel look and, if AgentCore is preferred, one more advisor pass on the S3-as-broker design.

## H. Advisor quorum (Codex, read-only, xhigh, 2026-09-13)

Codex agreed with rent-first on Vercel for a bounded v1 and with amending wave1 §2 by name, and corrected the spike on six points. All six are accepted and supersede §F where they conflict. Labels are Codex's: **D** from docs/code it read, **G** general knowledge, **S** its own judgement.

1. **Residency was overstated (D).** Vercel's standard DPA permits international processing; a region pin places *execution*, it does not establish all-data EU residency for artifacts, logs, support access, or failover. London (`lhr1`) is not an EU region. → Requirement (2) is met for execution placement only. Before any customer-facing residency claim: obtain the applicable DPA and subprocessor chain, confirm coverage of artifacts/logs/support/retention/transfers, and restrict failover geographically. Until then, promise only what is verified.
2. **Ephemerality is not the Vercel default (D).** Persistence defaults on; stopping a sandbox snapshots its files, and snapshots survive sandbox deletion. → `persistent:false` on every create, no tenant-bearing reusable images, and a cleanup test that proves no snapshot or orphan survives a run.
3. **Egress needs adversarial tests, not a flag (D/S).** SNI allowlists permit domain fronting; Vercel's request matchers do not deny unmatched traffic, so a match-conditioned forward can be bypassed; CIDR-only allows can leave DNS open. → Forward *every* request for one exact broker hostname unconditionally and reject unwanted methods/paths at the broker. Test DNS exfiltration, IPv6, raw-IP, metadata, and alt-protocol bypasses before v1 ships. No public sandbox ports.
4. **Time and money must be enforced provider-side (D/G).** Vercel reports CPU only after stop and allocated memory rather than peak; Pro sessions cap at 24 h; our loop's wall-clock timer aborts the SDK child and cannot bound a *remote* sandbox. → Provider-side deadlines, an orphan reaper, per-tenant concurrency and daily compute budgets, and a worst-case reservation at run start. A busy loop or miner must be killable *during* a step, not only between model requests.
5. **Interface: two layers, not one (S).** Keep the E2B-shaped adapter private. The loop sees `stageInputs / runStep / collectOutputs / cancel` as MCP capabilities carrying limits, identity, and artifact handles, exposed through the existing tool guards and §5 tighten-only policy — never shell strings or provider handles. Portability is proven by behaviour tests, not matching method names.
6. **Do not reuse `llmEgressProxy` as the broker transport (D).** It is loopback-only, CONNECT-only, opaque after connect, its bearer is reusable until revoked with no expiry, grants live in process memory, and audit failures are swallowed; a remote sandbox cannot reach it, and it cannot enforce read-only HTTP semantics, object authorization, or response-size caps. → Reuse its resolve-and-pin and revocation *logic* in a small, separate, regional HTTP artifact broker process with narrow storage credentials, durable run/lease authorization, rate limits, and authenticated sandbox identity. One guest-visible destination; multi-host grants would enlarge authority for nothing.

Also noted: the "5–10× cheaper" self-host figure is compute-only, not total cost (idle pools in two regions, redundancy, labour); Codex's illustrative monthly compute at 10-minute runs, 1 vCPU/2 GB: 100 runs/day ≈ $28–85 Vercel vs ≈ $9 DO, 10,000 runs/day ≈ $2,760–8,520 vs ≈ $900 (S). And: gVisor v2 is a *security-boundary change*, to be reviewed on its own merits when measured savings would fund the operations, never adopted on volume alone.

Artifact-handle hardening Codex asked for (S), carried into the spec: run/org/object-scoped handles only, no arbitrary fetch URLs, expiring grants, caps on request count, total and decoded bytes, file count, disk, and stdout; reject traversal and symlink escapes at collection; staging only data the run is authorized for — "read-only" is not org-wide read authority.
