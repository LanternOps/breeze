**Two expectation corrections for this row (not bugs, but the checklist's wording is wrong):**

- ⚠️ **There is no `Installing` state on this path, by construction.** The `deployment_status` enum does carry `downloading`/`installing`/`running`, but no software writer ever sets them: `applySoftwareInstallResult` flips `pending` → `completed`/`failed` in one guarded step. The list API's computed aggregate (`computeSoftwareDeploymentAggregateStatus`) can only report `in_progress` for a **multi-device** deployment with a mix of pending and finished results — a policy-owned install is one device per deployment, so it is `pending` for the ~1.5 s of flight and then terminal. The observed walk is therefore **`Pending → Completed`** and **`Pending → Failed`**, not `Installing → Installed`. Worth rewording the row (and, if the intent was a real in-flight state, worth an issue — the agent knows when it is downloading vs. executing and reports nothing until the end).
- ⚠️ **`GET /software-policies/:id/install-preview` returns `eligibleDeviceCount: 0` until the policy has been evaluated at least once**, even with the config-policy link and assignment correctly in place. This is what the 2026-09-16 sweep hit; it is not an assignment bug. The API log says so explicitly (`[InstallPreview] policy …: returning 0 with NO compliance rows for any of 1 resolved device(s) — the policy has not been evaluated yet, so this is "not measured", not "nothing to install"`), but the number the operator sees is an honest-looking `0`. W04's UI must not render this as "0 devices will be affected". Order of operations for anyone re-running this: assign → **check** → preview.

**Also worth knowing (cost me ~10 minutes):** only ONE software policy applies per device. `resolveDeviceIdsForSoftwarePolicy` verifies each candidate's *winning* config policy points at that software policy (closest-wins), so a second config policy assigned at the same level to the same device makes the second software policy resolve to **zero devices and evaluate silently** — no row, no log line.
