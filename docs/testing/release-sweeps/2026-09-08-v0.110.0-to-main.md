## Release-cut findings surfaced during setup

**R1 — Forced MFA for every existing Partner Admin on upgrade (#4491, migration `2026-10-11-170000-partner-admin-force-mfa-reconcile.sql`).** Intended: the migration flips `roles.force_mfa` to true on the global system Partner Admin template AND every tenant copy, bumping `permissions_epoch` so each member without an enrolled factor gets `428 mfa_enrollment_required` and is sent to `/auth/mfa/setup?forced=1` on their next request. Observed on this stack: the seeded `admin@breeze.local` (Partner Admin) could not reach the app after login until enrolling. Relief valve documented in the migration header: `MFA_FORCE_FOR_PARTNER_ADMIN=false` (suppresses only the role-force component). **Release cut must:** (a) put this in the release notes as a breaking behaviour change for hosted AND self-hosted, (b) decide whether EU/US deploy with the valve set for a grace period, (c) note that the valve env var needs to be mapped through compose on the droplets if used. Sweep stack runs with the valve set so the seeded admin can log in; Group 4 verifies the forced flow explicitly with a fresh Partner Admin user. **Disposition (Todd, 2026-09-08):** do not enforce by default this release → PR #5307 flips the env default to OFF (opt-in via `MFA_FORCE_FOR_PARTNER_ADMIN=true`); notification-period rollout planned for next release as #5306. Release-day check: droplet `.env` must not pin the var to true.
