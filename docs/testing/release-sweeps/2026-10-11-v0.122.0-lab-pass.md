### Observations (not FAILs)
1. **An identity-bound payload enqueued by the move is always lost on the assertion beat.** On both platforms, every move's `device_org_changed` / `device_site_changed` peripheral reconcile went out on the same beat as the assertion and was `rejected / wrong_identity`. Recovery waited for the next `periodic_drift` sweep (every 15 min); here it took 1–15 min. The PR documents this as out of scope. Operator effect: up to about 15 min of the old policy after a move.
2. Linux self-restart: journald shows `Killing process <pid> (systemctl) with signal SIGKILL` on each identity restart. The in-cgroup `systemctl restart` client is killed when the unit stops. The restart still completes every time because systemd already queued the job. This comes from the existing `updater.Restart()` used by self-update, not something new here.
3. The server-side assertion path never logs a success, so without packet capture there is no operator-visible trace that an assertion was sent. The agent log line is the only evidence.
