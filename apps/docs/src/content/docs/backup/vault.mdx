A local vault mirrors your backup snapshots from cloud storage to a disk attached to the device — an external or USB drive, or a local disk. This gives you fast, offline recovery when the cloud is unreachable or when you need to restore large datasets without waiting for a download.

---

## Creating a Vault

<Steps>
1. Go to **Backup > Device Backup > Vault**.
2. Click **Add New Vault**.
3. Fill in the vault configuration:
   - **Device** — which device the vault is attached to
   - **Vault path** — a dedicated directory on a local disk or USB drive attached to the device
   - **Type** — Local Disk or USB Device
   - **Retention count** — number of snapshots to keep locally (1–100)
4. Click **Save**.
</Steps>

The vault appears in the list with a **Never synced** status.

Use a dedicated vault directory. New roots and newly written directories and objects are private to the agent service account. An existing non-private root pauses vault operations with a migration diagnostic; Breeze does not change its permissions automatically. Verify the path, then migrate to a new private location or harden it explicitly before retrying; the steps are in [Local destination permissions](/backup/storage/#local-destination-permissions). Review existing object permissions too; Windows descendant ACLs require a separate maintenance pass.

SMB and NAS shares are not supported as vaults. Breeze refuses to save a vault of type SMB share or a vault whose path is not an absolute path on a volume of the device (UNC and device paths are refused), and the agent refuses a vault on a network volume, including a drive letter mapped to a share. A vault saved on a share before this release is refused on the device until you move it to an attached disk; you can still deactivate or delete it. Do not add the device's computer account to the file server's Administrators group to make a share pass the checks. See [Network shares](/backup/storage/#network-shares).

## Syncing a Vault

Click the **Sync** button on a vault to trigger an immediate sync. The sync process:

1. Compares local vault contents against the latest cloud snapshots
2. Downloads only missing files (incremental sync)
3. Removes snapshots that exceed the retention count
4. Updates the vault status and last sync timestamp

<Aside type="tip">
  Vaults sync intelligently — they only download files that aren't already present locally. After the initial sync, subsequent syncs are fast and bandwidth-efficient.
</Aside>

---

## Vault Status

| Status | Meaning |
|--------|---------|
| **Syncing** | A sync operation is in progress |
| **Completed** | Last sync finished successfully |
| **Failed** | Last sync encountered an error — check the vault path and connectivity |
| **Never synced** | Vault was created but hasn't been synced yet |

---

## Managing Vaults

- **Deactivate** — temporarily disables the vault without deleting its configuration. No further syncs will run. Reactivate at any time.
- **Delete** — removes the vault configuration. Does not delete the data already on the local storage.

---

## When to Use Vaults

| Scenario | Recommendation |
|----------|---------------|
| **Critical servers** | Pair cloud backup with a local vault for sub-minute restore times |
| **Remote offices with slow WAN** | Vault to a disk attached to the server so restores don't depend on internet bandwidth |
| **Compliance** | Keep an offline copy on USB or air-gapped storage |
| **Disaster recovery** | Local vaults provide a second restore option if the cloud provider is down |
