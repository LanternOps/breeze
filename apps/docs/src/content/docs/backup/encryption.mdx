Backup data at rest is protected by your storage destination's own encryption, not by a Breeze-managed cipher on the agent. Today that means **S3 server-side encryption (SSE)** — there is no agent-side encryption step, and no client-managed key is currently used to encrypt or decrypt any live backup.

---

## What's Actually Enforced

Encryption is a toggle on your [storage configuration](/backup/storage/), and it's only enforceable for **Amazon S3** (or S3-compatible) destinations:

- **SSE-S3 (AES-256)** — set `serverSideEncryption` to `AES256` in the provider config. S3 encrypts every object with an AWS-managed key.
- **SSE-KMS** — set `serverSideEncryption` to `aws:kms` and provide a `kmsKeyId` (or `keyArn`). S3 encrypts objects using your own KMS key.

If you enable encryption on a **Local disk** destination, or on S3 without a recognized `serverSideEncryption` value, Breeze rejects the configuration as unsupported — there is no client-side fallback cipher for those cases.

## Encryption Keys Manager (Early Access)

Go to **Backup > Device Backup > Encryption** to see the key manager.

<Aside type="caution">
  Client-side encryption keys are **not available yet**, and this page is **read-only**. Keys here are not used to encrypt, protect, or otherwise affect any actual backup or snapshot — the agent has no encryption capability of its own to apply them to. The page does not offer create, rotate, or deactivate actions; the key model is planned for a future release.
</Aside>

If any keys already exist for your organization, the list shows them read-only:
- Key name
- Key type (AES-256 or RSA-2048)
- Status: **Active** (green) or **Inactive** (gray)
- Created date
- Expiry date (if set)

Backups are encrypted at rest by the storage provider today, where the destination supports it, as described above.

---

## How to Actually Protect Backup Data Today

- **In transit** — all backup data is transferred over HTTPS (TLS 1.2+)
- **At rest** — for S3 destinations, enable server-side encryption (SSE-S3 or SSE-KMS) on the storage configuration, as described above
- For local disk destinations, rely on your own disk/volume-level encryption — Breeze does not encrypt data written to a local path
