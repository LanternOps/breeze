This page lists all backup API endpoints for teams building integrations or automations against the Breeze Backup system. For UI-based workflows, see the other pages in the Backup section.

<Aside type="note">
  All backup endpoints require authentication and are scoped to the caller's organization. Organization-scoped tokens are automatically restricted to their own data. Partner-scoped tokens work when the partner has access to exactly one organization.
</Aside>

---

## Storage Configurations

| Method | Path | Description |
|--------|------|-------------|
| GET | `/backup/configs` | List all configurations |
| POST | `/backup/configs` | Create a configuration |
| GET | `/backup/configs/:id` | Get configuration details |
| PATCH | `/backup/configs/:id` | Update configuration fields (shallow-merged) |
| DELETE | `/backup/configs/:id` | Delete a configuration |
| POST | `/backup/configs/:id/test` | Test storage connectivity |

## Backup Jobs

| Method | Path | Description |
|--------|------|-------------|
| GET | `/backup/jobs` | List jobs (filter: `status`, `deviceId`, `date`, `from`, `to`) |
| GET | `/backup/jobs/:id` | Get job details |
| POST | `/backup/jobs/run/:deviceId` | Trigger manual backup |
| POST | `/backup/jobs/:id/cancel` | Cancel a running/queued job |
| GET | `/backup/jobs/run-all/preview` | Preview a run-all: counts of eligible, offline, and already-running devices |
| POST | `/backup/jobs/run-all` | Trigger a manual backup on every device with an assigned backup policy |

## Bare Metal Recovery

| Method | Path | Description |
|--------|------|-------------|
| POST | `/backup/bmr/tokens` | Generate recovery token (`snapshotId`, optional `expiresInHours`, `restoreType`, `targetConfig`) |
| GET | `/backup/bmr/tokens/:id` | Get recovery token metadata |

### Boot Media

Bootable ISO images for BMR, built from a recovery token. Currently `linux`/`amd64`/`iso` only.

| Method | Path | Description |
|--------|------|-------------|
| GET | `/backup/bmr/boot-media` | List boot media artifacts (filter: `tokenId`, `snapshotId`, `status`) |
| POST | `/backup/bmr/boot-media` | Request boot media for a token (`tokenId`, optional `bundleArtifactId`) |
| GET | `/backup/bmr/boot-media/:id` | Get boot media artifact details and status |
| GET | `/backup/bmr/boot-media/:id/download` | Download the boot media ISO |
| GET | `/backup/bmr/boot-media/:id/signature` | Download the boot media's detached signature |

## Cloud-to-Cloud (C2C)

<Aside type="caution">
  Sync and restore execution are not yet implemented. `POST /c2c/configs/:id/run` creates a job that immediately fails with `c2c_sync_not_implemented`, and restore jobs fail the same way with `c2c_restore_not_implemented`. Connection and config setup below work today.
</Aside>

| Method | Path | Description |
|--------|------|-------------|
| GET | `/c2c/m365/config` | Check if platform M365 app is configured |
| GET | `/c2c/m365/consent-url` | Generate Microsoft admin consent URL |
| GET | `/c2c/m365/callback` | OAuth callback (public, CSRF-protected) |
| GET | `/c2c/connections` | List C2C connections |
| POST | `/c2c/connections` | Create connection (manual mode) |
| GET | `/c2c/connections/:id` | Get connection details |
| DELETE | `/c2c/connections/:id` | Revoke a connection |
| POST | `/c2c/connections/:id/test` | Test a connection; for a platform-app connection this also refreshes (re-authorizes) its access token |
| GET | `/c2c/configs` | List C2C backup configs |
| POST | `/c2c/configs` | Create/update backup scope and schedule |
| POST | `/c2c/configs/:id/run` | Trigger a sync (fails immediately — not yet implemented) |
| GET | `/c2c/items` | Search/browse backed-up items (filter: `configId`, `userEmail`, `itemType`, `search`) |
| GET | `/c2c/dashboard` | Connection, item, and storage summary stats |
| POST | `/c2c/restore` | Restore items by id (fails immediately — not yet implemented, see caution above) |
| GET | `/c2c/restore/:id` | Get a restore job's status |
