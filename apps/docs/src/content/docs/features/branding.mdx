Breeze's data model supports white-label branding -- logo, colors, custom CSS, and a custom domain -- at both the **partner (MSP)** and **organization (customer)** levels, read by the end-user portal, quotes, and invoices at render time. Settings > Organization and Settings > Partner each have a **Branding** tab for entering an appearance preference, and Settings > Organization > Portal controls the portal's feature toggles and support-contact fields.

<Aside type="note">
  This page covers branding for **post-login** surfaces: the dashboard and the end-user portal. Customizing the MSP **login screen** itself (logo, accent color, headline) is a separate partner-level feature — see [Login Page Branding](/reference/sso/#login-page-branding). Outbound customer mail (tickets, quotes, invoices, and portal invites) is edited under **Settings → Partner → Email templates**, not here.
</Aside>

<Aside type="caution">
  What reaches customers depends on the level:

  - **Logo and colors resolve the same way everywhere.** The logo and colors saved under **Settings > Partner > Branding** are the default for every organization. A value saved on **Settings > Organization > Branding** overrides it for that one customer, field by field (see [Organization logo and colors](#organization-logo-and-colors)).
  - **Where they appear.** The logo appears in the end-user portal, on quotes and invoices (the web views and the PDFs), on agreement signing pages, and on report PDFs (an uploaded image only). The primary color is the accent on documents and report PDFs, and on documents shown in the portal. The secondary color sets headings on quote PDFs when it is dark enough to read, and is the accent on report PDFs. The portal's navigation colors come from its own chrome accent setting.
  - **Custom domains and favicons are not configurable yet.** There is no dashboard control or API for writing them.
  - **Custom CSS reaches the portal.** The **Custom CSS** field on **Settings > Organization > Branding** is saved with the organization's portal settings and injected into portal pages, after the partner's Custom CSS.

  Outbound email templates (**Settings → Partner → Email templates**) edit the inner HTML of customer ticket, quote, invoice, and portal-invite mail; they do not change the email card's accent bar and do not pull colors from the Branding tab.
</Aside>

---

## Overview

Branding is configured at two levels:

- **Partner (MSP)** -- the logo, colors and custom CSS that apply to all of the partner's managed organizations by default.
- **Organization (customer)** -- an override of the logo and colors for one customer, its own custom CSS, and the portal's feature toggles and support-contact fields (see [Organization Branding](#organization-branding)).

---

## Logo Customization

Breeze currently supports a single logo per organization and per partner (MSP) -- there is no separate dark-mode variant or favicon upload today.

### Uploading a Logo

<Steps>

1. Navigate to **Settings > Organization > Branding** (or **Settings > Partner > Branding** to set the MSP-wide default).

2. In the **Logo** section, upload an image file. The partner tab also accepts a pasted hosted image URL.

3. A preview appears immediately in the editor.

4. Click **Save** to persist the changes.

</Steps>

<Aside type="caution">
  Logo URLs are sanitized before rendering to prevent XSS attacks. Hand-typed `javascript:` URLs and pasted `blob:` URLs are rejected. The portal, quotes, invoices and agreement pages only show a logo that was uploaded or uses `https://`. An organization logo saved through the API must be a PNG data URL or an `https://` URL.
</Aside>

<Aside type="caution">
  There is no dedicated file-storage upload for logos yet. Both editors resize an uploaded image client-side, encode it as PNG and store it inline (capped at roughly 400 KB), so large or high-resolution source images are scaled down or rejected. PDFs (quotes, invoices, reports) only draw an uploaded image; a hosted URL logo prints as the company name there.
</Aside>

## Color Customization

Two brand colors apply to customer documents and the portal:

| Color | When none is set | Usage |
|-------|---------|-------|
| **Primary** | `#2563eb` (blue) | Accent on quotes, invoices, other customer documents and report PDFs, and the portal's document accent |
| **Secondary** | the renderer's default | Heading color on quote PDFs, when dark enough to read on white, and accent on report PDFs. The portal does not use it |

### Setting Colors

Colors are entered as hex values (3 or 6 digit). The editor provides both a color picker and a text input. On the organization tab an invalid hex value blocks the save, and a blank field inherits the partner's color.

<Steps>

1. Open **Settings > Organization > Branding** (or **Settings > Partner > Branding**).
2. Use the color pickers or enter hex codes in the **Primary color** and **Secondary color** fields.
3. Click **Save**.

</Steps>

<Aside type="note">
  The organization colors are saved through `PATCH /organizations/:id/portal-settings` (see [API Reference](#api-reference)); the partner colors with the rest of the partner settings.
</Aside>

### Contrast Calculation

The branding editor automatically calculates text contrast for each color swatch. Text on colored backgrounds uses white (`#f8fafc`) for dark colors and dark (`#0f172a`) for light colors, based on relative luminance:

```
luminance = (0.299 * R + 0.587 * G + 0.114 * B) / 255
text color = luminance > 0.6 ? dark : light
```

This ensures buttons and headers remain readable regardless of the chosen brand colors.

## Organization Branding

Each organization has its own branding record in the `portal_branding` table, keyed by `orgId` (unique constraint). The logo and colors override your partner Branding when set, and are written from **Settings > Organization > Branding**. There is currently no admin-facing way to write the favicon, accent color or custom domain. The portal feature toggles and support-contact fields (`enableTickets`, `enableAssetCheckout`, `enableSelfService`, `enablePasswordReset`, `supportEmail`, `supportPhone`, `welcomeMessage`, `footerText`) are set from **Settings > Organization > Portal**, and `customCss` from the **Custom CSS** field on **Settings > Organization > Branding**.

### Branding Schema

| Field | Type | Description |
|-------|------|-------------|
| `logoUrl` | text | URL to the primary logo image |
| `faviconUrl` | text | URL to the favicon |
| `primaryColor` | varchar(50) | Primary brand color (hex) |
| `secondaryColor` | varchar(50) | Secondary brand color (hex) |
| `accentColor` | varchar(50) | Optional accent color (hex) |
| `customDomain` | varchar(255) | Custom portal domain (e.g., `support.acmecorp.com`) |
| `domainVerified` | boolean | Whether the custom domain's DNS has been verified |
| `welcomeMessage` | text | Plain-text welcome shown at the top of the customer's landing page (Dashboard when enabled, otherwise Proposals) and on the sign-in page of a verified custom domain. Line breaks are kept; HTML is shown as text |
| `supportEmail` | varchar(255) | Support email shown in emails and portal footer |
| `supportPhone` | varchar(50) | Support phone number |
| `footerText` | text | Custom footer text for the portal. Also printed on the organization's quotes and invoices, in place of the partner document footer |
| `customCss` | text | Injected CSS for fine-grained portal styling |
| `enableTickets` | boolean | Enable the ticket submission feature on the portal |
| `enableAssetCheckout` | boolean | Enable asset checkout/return on the portal |
| `enableSelfService` | boolean | Enable self-service tools on the portal |
| `enablePasswordReset` | boolean | Enable password reset on the portal |

### Organization logo and colors

The fields on **Settings > Organization > Branding** override your partner Branding for that one customer:

- **Logo** -- shown in that organization's portal and on its quotes, invoices, agreements and report PDFs.
- **Primary color** -- the accent color on its quotes, invoices, other customer documents and report PDFs.
- **Secondary color** -- the heading color on its quote PDFs, when dark enough to read, and the accent color on its report PDFs.

<Steps>

1. Open **Settings > Organization > Branding** for the customer.
2. Upload a logo, and enter a hex color (such as `#2563eb`) or use the color picker. Leave a field empty to use the partner's value, which the tab shows as the inherited value. **Remove** clears an organization logo.
3. Click **Save**. An invalid hex value blocks the save and nothing is written.

</Steps>

A logo uploaded on this tab in an earlier release was saved but never shown to customers. The tab offers it with a notice: **Save** starts using it, and **Remove** discards it. Colors saved in earlier releases are not carried over, because the tab used to save a default whether or not anyone chose a color.

### Org Branding Editor

**Settings > Organization > Branding** provides a simplified appearance editor compared to the partner-level one. It includes:

- **Logo upload** -- single logo
- **Primary and secondary color** pickers
- **Custom CSS** -- advanced styling overrides

To see the result, open the organization's portal, or use the staff **Customer view**.

<Aside>
  The org branding editor is available under **Settings > Organization** and requires the `organization:write` permission.
</Aside>

## Partner Branding

Partners (MSPs) set the logo, colors and custom CSS that apply by default to organizations under their management from **Settings > Partner > Branding**.

### Partner Branding Editor

The partner-level editor provides:

- **Logo** -- upload an image (stored inline, capped at roughly 400 KB) or paste a hosted image URL
- **Primary and secondary colors**
- **Theme** -- `light`, `dark`, or `system`
- **Custom CSS** -- added to the end-user portal of every organization under the partner (see [Custom CSS](#custom-css))

<Aside type="caution">
  The partner **logo** and **colors** apply to every organization that has not set its own, in the portal and on customer documents (see the caution near the top of this page). The partner **theme** is not used anywhere yet. A hosted logo URL must use `https://` to appear on customer documents.
</Aside>

## Custom Domains

Custom portal domains (e.g., `support.acmecorp.com`) are not configurable yet -- there is no admin control or API to set or DNS-verify a domain today. The underlying data model supports it (a domain only resolves branding once `domainVerified` is `true`), but that work hasn't shipped.

## Supported Assets

### Image Formats

| Format | Notes |
|--------|-------|
| PNG | Use transparent backgrounds for best results |
| JPEG, WebP | Accepted by the upload control, which re-encodes them as PNG |

### Size Recommendations

| Asset | Minimum | Recommended | Maximum |
|-------|---------|-------------|---------|
| Logo | 64 x 64 px | 512 x 512 px | Uploaded images are scaled down client-side to 800 px on the long side (smaller if needed to stay under 400 KB after encoding) |

### Custom CSS

Custom CSS is injected after the base stylesheet. It can be set at two levels, and both apply:

1. **Partner** (**Settings > Partner > Branding**) -- added to the portal of every organization under the partner.
2. **Organization** (the org's portal settings) -- added after the partner's CSS, so an organization rule overrides a partner rule for the same selector.

Use it for fine-grained control over portal appearance:

```css
/* Adjust portal header spacing */
.portal-header {
  letter-spacing: 0.04em;
}

/* Round card corners */
.portal-card {
  border-radius: 18px;
}

/* Custom font */
body {
  font-family: 'Inter', system-ui, sans-serif;
}
```

<Aside type="caution">
  Saving is refused when the CSS is longer than 65,536 characters or contains `@import`, `expression(`, `behavior:`, `-moz-binding`, or a `url()` that is not `https:` or `data:`. Otherwise the CSS is injected as written. Avoid CSS that breaks layout or hides critical UI elements.
</Aside>

## API Reference

### Organization Portal Settings

| Method | Path | Description |
|--------|------|-------------|
| GET | `/organizations/:id/portal-settings` | Get the portal feature toggles, support-contact fields, organization logo, colors and custom CSS, plus the inherited partner values |
| PATCH | `/organizations/:id/portal-settings` | Update those fields |

<Aside type="caution">
  These are the only writable portal branding fields today, plus `customCss`, `logoUrl`, `primaryColor` and `secondaryColor` (which the organization **Branding** tab saves through this endpoint). The colors must be `#rgb` or `#rrggbb` hex values. `logoUrl` must be a PNG data URI of at most 400 KB, or an `https://` URL. `null` inherits the partner's value; `GET` also returns `partnerLogoUrl`, `partnerPrimaryColor` and `partnerSecondaryColor`, the inherited values. The other visual fields (favicon, accent color, custom domain) are rejected by this endpoint.
</Aside>

### Portal Branding

| Method | Path | Description |
|--------|------|-------------|
| GET | `/portal/branding/:domain` | Public. Resolve branding by verified custom domain |
| GET | `/portal/branding` | Requires an authenticated portal session. Resolves branding for the logged-in user's own organization |

<Aside>
  Only `/portal/branding/:domain` is public (no authentication required), since it is called by the portal frontend before the user logs in. Unverified custom domains return 404. `/portal/branding` (no domain segment) requires a valid portal session and returns the caller's own organization's branding. Both resolve `logoUrl`, `primaryColor` and `secondaryColor` from the organization's record, falling back to the partner's Branding. An organization with no portal branding record gets only its partner's logo, colors and custom CSS (no feature flags), or 404 when the partner has set none.
</Aside>

### Request / Response Examples

**Get portal settings:**

```bash
GET /organizations/:id/portal-settings
Authorization: Bearer <token>
```

**Response (200):**

```json
{
  "data": {
    "orgId": "uuid",
    "enableTickets": true,
    "enableAssetCheckout": false,
    "enableSelfService": true,
    "enablePasswordReset": true,
    "supportEmail": "it@acmecorp.com",
    "supportPhone": "+1-555-0123",
    "welcomeMessage": "Welcome to Acme IT Support",
    "footerText": "Powered by Acme IT"
  }
}
```

**Update portal settings:**

```bash
PATCH /organizations/:id/portal-settings
Content-Type: application/json
Authorization: Bearer <token>

{
  "supportEmail": "it@acmecorp.com",
  "welcomeMessage": "Welcome to Acme IT Support"
}
```

**Resolve portal branding by domain:**

```bash
GET /portal/branding/support.acmecorp.com
```

**Response (200):**

```json
{
  "branding": {
    "id": "uuid",
    "orgId": "uuid",
    "logoUrl": "https://storage.breeze.app/branding/acme/logo-light.png",
    "faviconUrl": "https://storage.breeze.app/branding/acme/favicon.ico",
    "primaryColor": "#1e40af",
    "secondaryColor": "#f59e0b",
    "accentColor": null,
    "customDomain": "support.acmecorp.com",
    "domainVerified": true,
    "welcomeMessage": "Welcome to Acme IT Support",
    "supportEmail": "it@acmecorp.com",
    "supportPhone": "+1-555-0123",

  }

```

## Troubleshooting

**Logo doesn't show up on quotes or invoices.**
Quotes and invoices use the organization's logo if it has one, otherwise the logo saved under **Settings > Partner > Branding**. Check that a logo is saved at one of those levels: an uploaded image is stored inline, and a pasted URL must start with `https://` (an `http://` URL is not used on customer documents). PDFs draw only uploaded images, so a pasted URL shows the company name instead.

**Logo doesn't show up on the customer portal.**
The portal uses the same logo as documents: the organization's, otherwise the partner's. A logo uploaded on the organization tab in an earlier release has to be saved once more to take effect (see [Organization logo and colors](#organization-logo-and-colors)).

**"Failed to fetch branding" error in the editor.**
This typically indicates an authentication issue. The editor calls `GET /organizations/:id/portal-settings` (organization level) with the user's session token. If the token has expired, the editor redirects to the login page. Ensure the user has the `organization:write` permission.
